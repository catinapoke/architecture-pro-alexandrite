# Решение

## Кому требуется

Для всех логов по умолчанию проставляются поля 

- trace_id
- время

Для всех API запросов логируем INFO уровень и дополнительно поля

- входные параметры
- путь 
- http код
- код ответа

Для каждой ошибки используется уровень ERROR. Для каждой ошибки логируем время, текст ошибки, trace_id и дополнительно код сущности с которой работали. Текст ошибки должен однозначно показывать суть ошибки и место. 

Логи собираются для систем MES API, CRM API и Shop API. 

Дополнительно логировать события смены статуса заказа с дополнительными полями номера заказа и id пользователя инициировавшего смену статуса (для MES API это будет оператор).

## Мотивация

Логирование уменьшит lead time, поскольку это напрямую повлияет на скорость решения проблем на тесте и проде. 

lead time увеличит количество выпускаемых фичей за месяц. 

Дополнительно логирование может уменьшить время решения проблемы на проде и при правильных процессах, если ставить цель приблизить количество ошибок на проде к нулю, то и количество инцидентов на проде. 

Логирование и трейсинг в первую очередь следует настраивать в MES API, поскольку после запуска API и взятия заказов от других компаний потери увеличились. Это может быть причиной проблем в MES API. 

Далее добавить логи и трейсы в CRM API и Shop API, поскольку они должны быть настроены в каждом серисе компании.

## Предлагаемое решение

Логи можно собирать с помощью Grafana Alloy и Loki. Это отлично ложиться в технологии, которые были предложены ранее. Далее собранные логи можно отобразить в Grafana. 

Для безопасности в логи запрещено писать любые чувствительные данные - логины, пароли, телефоны и прочее без маскирования.

Если нужно залогировать, то лучше ограничиться внутренним идентификатором. Доступ только поддержке и команде разработки по авторизации в Grafana.

Сроки хранения 30 дней + задать размер логов под каждый сервис, чтобы ограничить максимальное выделенно хранилище под логи.
